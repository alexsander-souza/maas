# Implementation Plan: Custom Boot Assets

**Branch**: `custom_boot_assets` | **Date**: 2026-05-22 | **Spec**: [spec.md](spec.md)

**Jira**: MAASENG-5494

## Summary

Add operator-supplied bootloader and kernel as first-class MAAS assets. Operators upload bootloader tarballs or kernel+initrd pairs via new v3 API endpoints. At deploy time, they select a custom asset by name on the v2 deploy endpoint. The Region stores the selection on the Node and returns the custom kernel/initrd paths from `get_boot_config` at PXE boot time; custom bootloaders are delivered via a per-host DHCP `filename` directive. All upload logic is extracted from the existing `upload_custom_image` handler into the service layer and shared across all upload paths.

No new database tables are required. Custom assets reuse `BootResource → BootResourceSet → BootResourceFile → BootResourceFileSync`. Two new partial unique indexes enforce identity uniqueness. Two nullable fields are added to the Node model.

## Technical Context

**Language/Version**: Python 3.14 (service layer, API, legacy region); Go 1.24.4 (agent — not touched by this feature)

**Primary Dependencies**: FastAPI + Pydantic (v3 API), SQLAlchemy Core (repositories), Django + Twisted (legacy region controller), Tempita (DHCP template rendering), Alembic (schema migrations)

**Storage**: PostgreSQL via SQLAlchemy Core (v3 path) and Django ORM (legacy path); local filesystem at `get_bootresource_store_path()` (`/var/lib/maas/image-storage/`) for binary files

**Testing**: `bin/test.region` (legacy/DHCP/RPC), `make test-py` (service layer + API), `bin/pytest` (integration)

**Target Platform**: Linux server (Region Controller + Rack Controller)

**Project Type**: Multi-tier web service (FastAPI v3 API + Django legacy API)

**Performance Goals**: Upload available for deploy selection within 60 s of completion; boot parameter response unchanged in latency (single extra DB lookup for custom kernel check)

**Constraints**: DHCP option 67 combined path ≤ 128 bytes; bootloader tarball extraction path must use a short fixed prefix; SHA-256 must be verified before any DB record is committed

**Scale/Scope**: Low write frequency (admin-only uploads); high read frequency (boot parameter lookup on every PXE boot)
